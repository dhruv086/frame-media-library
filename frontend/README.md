# Frame · Media Asset CMS

React + Vite, plain JavaScript/JSX, and plain CSS. Runtime dependencies are only `react` and `react-dom`.

```sh
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. Node 20.19+ or 22.12+ is required by Vite. In Windows PowerShell with restricted script execution, use `npm.cmd` instead of `npm`.

Copy `.env.example` to `.env.local` to configure the API. The default is `http://localhost:4000`, matching the backend's media routes. Its readiness endpoint is `/api/health`. Restart Vite after changing environment variables.

## Features

- Bucket selection, filename search with a 300 ms debounce, format/date filters, and pagination.
- The development setup uses one bucket, shown as **Dhruv-assets**; its storage identifier remains `dev-assets` to preserve existing assets and URLs.
- Multiple uploads with validation, real XMLHttpRequest progress, independent results, and retry after server/network errors.
- Image/video previews, complete metadata, and optimized image variants with actual byte sizes and savings.
- Video optimization with resolution, bitrate, H.264/MP4 or VP9/WebM, CRF quality,
  queued/processing/error status, retries, saved variants, and playable output.
- Same-format replacement with stable original URL and UI-only version parameters to refresh thumbnails/previews.
- Alt text, tag chips, clearable expiry, copy URL, and confirmed deletion.
- Four-second notifications, skeletons, useful empty/error states, mobile layouts, focus trapping/restoration, Escape/backdrop dismissal, and reduced-motion support. Dialog dismissal is disabled during a write to keep its result visible.

## Backend integration

The frontend follows `backend/API.md`. The header checks database readiness, and asset dialogs fetch current metadata before previewing, replacing, editing, or deleting an asset.

| Operation | Request                                                  | Response                                     |
| --------- | -------------------------------------------------------- | -------------------------------------------- |
| Health    | `GET /api/health`                                        | `{ status, database }`                       |
| Buckets   | `GET /buckets`                                           | `{ buckets: [{ name, publicUrl }] }`         |
| Gallery   | `GET /assets?bucket=&q=&format=&from=&to=&page=&limit=`  | `{ assets, total, page, limit, totalPages }` |
| Details   | `GET /assets/:id`                                        | Asset                                        |
| Upload    | `POST /assets`, multipart `file` and `bucket`            | Asset                                        |
| Replace   | `PUT /assets/:id/replace`, multipart `file`              | Updated asset                                |
| Edit      | `PATCH /assets/:id`, JSON `{ altText, tags, expiresAt }` | Updated asset                                |
| Delete    | `DELETE /assets/:id`                                     | `204`                                        |
| Optimize  | `GET /assets/:id/optimized?w=&q=&format=`                | Image bytes or redirect to image             |
| Video     | `POST /assets/:id/transcode`, JSON encoding settings    | `202` job or `200` cached video variant       |

Errors use `{ error: { code, message } }`. Assets expose `id`, `originalName`, `format`, `mimeType`, `size`, `width`, `height`, `duration`, `bucket`, `key`, `url`, `thumbnailUrl`, `version`, `altText`, `tags`, `expiresAt`, and timestamps. The selected first bucket is both the gallery filter and upload destination. Pages contain 12 assets. Overview image/video counts and storage explicitly describe the current page; total count reflects active filters. Replacement requires exact extension equality, including `jpg` versus `jpeg`, as the server does. The 200 MB limit uses 200 × 1024 × 1024 bytes. Expiry is the end of the selected date in UTC; clearing it sends `null`.

Optimized previews use a blob fetch (with redirects followed) so sizes reflect actual output. The public storage endpoint must permit browser CORS requests. Original URLs are preserved when copied or stored. No authentication scheme was specified.

In an image preview, change width/format/quality and select **Generate preview**
to apply them. The generated image is decoded to show its actual width and height.
Images are never enlarged to fill the preview; larger images scale down to fit.
The Original/Optimized toggle changes the displayed format, dimensions, and file
size. **Open optimized** opens the generated bytes in another tab. If settings
change after generation, a reminder indicates that the current output needs to
be regenerated. A failed conversion leaves the previous working preview intact.

For a video, open **Preview**, choose resolution (480p/720p/1080p), bitrate limit
in kbps, codec, and CRF quality, then select **Generate video preview**. The UI
polls the asset's persisted job and plays the result when ready. Processing
continues if the modal is closed; reopen it to resume checking progress or select
a saved variant. Use **Original / Optimized** to compare and **Open optimized**
to open the public output. Actual dimensions, file size/savings, audio/video
codecs, and measured total bitrate describe the selected file. Smaller videos
are not upscaled; bitrate limits apply to video, so audio/container overhead can
make the measured total bitrate higher. Failed jobs provide a retry action.

Use the asset's **Edit metadata** action to change alt text, add/remove tag chips,
or set/clear its expiry date. Metadata edits preserve the original and variants.

## Validation

```sh
npm test
npm run build
```

`npm test` covers error envelopes, cancellation/network failures, exact query and PATCH shapes, XMLHttpRequest progress, duplicate errors, file validation, cache-busting, and expiry boundaries.

Read-only real-server contract check (uses the same `.env.local` as Vite):

```powershell
npm.cmd run test:api
```

With Vite and the real backend running, `npm run test:browser` runs a dependency-free headless Edge/CDP check. It creates uniquely named temporary media, checks search, image optimization, metadata/tags, replacement, multi-file upload/progress/duplicate errors, responsive dialogs, and deletion, then removes only its own fixtures. Set `BROWSER_PATH` for another Chromium executable and `VITE_API_URL` for another API. Screenshots go to ignored `test-results/`; the isolated browser profile is also ignored.

The browser suite checks health and fresh asset-detail requests along with media workflows at 1440 px and 390 px. A duplicate upload intentionally returns an HTTP 409 visible in the browser network log.
It also verifies 200px/400px rendering without enlargement, actual decoded
dimensions, Original/Optimized details, the optimized link, mobile scaling for a
larger image, and recovery from invalid optimized bytes.
Video checks generate real input with the backend's installed FFmpeg binary,
exercise both codecs and custom settings, play the resulting files, verify
decoded dimensions and optimized links, reopen saved variants, edit video
metadata, and check mobile layout. Install backend dependencies before this suite.
